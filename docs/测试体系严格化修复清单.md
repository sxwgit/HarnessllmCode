## 3. 必须遵守的改造规则

### 3.1 测试分类规则

每个测试都必须属于以下三类之一：

1. `behavioral`
   直接验证运行时行为、状态变化、副作用。
2. `anti-cheat`
   验证“看起来像通过、实际上不合规”的输入会被拒绝。
3. `static`
   仅验证纯静态常量、schema、正则、版本号等不需要运行时执行的内容。

### 3.2 严格性规则

以下规则必须执行：

1. `P0/P1` 用例禁止只用 `readHarnessFile()` + `toContain()` 作为主断言。
2. 关键门禁用例必须至少包含一个副作用断言：
   - 状态未推进
   - Git 未提交
   - Tag 未创建
   - 后续产物未生成
   - 日志/审计已记录
3. 每条关键规则至少要有：
   - 1 个正例测试
   - 1 个反例测试
4. 如果一个测试只能证明“代码里写了这句话”，那它不算严格测试。

### 3.3 静态测试保留范围

允许保留静态测试的内容只有：

1. `FRAMEWORK_VERSION`
2. Zod schema 常量
3. 固定命名正则
4. 不依赖运行时路径的纯函数常量映射

除此之外，原则上都应转成行为测试或反作弊测试。
