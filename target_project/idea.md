# 文档开发思路

我希望你参考claude code 进行开发，下面是开发路线图

## 简化版开发路线图 (MVP: 20% 功能 = 80% 价值)

### 第一阶段: 核心骨架 (能让系统跑起来)

| 优先级 | 模块 | 功能 | 原因 |
|--------|------|------|------|
| P0 | **大模型交互** | Anthropic API 流式调用 + Tool-Use Loop | 这是整个系统的心脏 |
| P0 | **工具系统** | Tool 类型定义 + 注册机制 | 没有工具，Agent 无法行动 |
| P0 | **核心工具** | BashTool, FileReadTool, FileWriteTool, FileEditTool | 最小可用工具集 |
| P0 | **搜索工具** | GlobTool, GrepTool | 代码理解的基础能力 |
| P0 | **CLI 入口** | 基本的命令行解析和启动 | 用户入口 |
| P0 | **权限系统** | 基础的权限检查和用户确认 | 安全底线 |
| P0 | **上下文管理** | 系统提示词构建 + 消息规范化 | 对话的基础 |

### 第二阶段: 基础体验 (能日常使用)

| 优先级 | 模块 | 功能 | 原因 |
|--------|------|------|------|
| P1 | **子 Agent** | AgentTool 基础版 | 复杂任务需要并行/分工 |
| P1 | **上下文压缩** | Compact 基础版 | 长对话不可避免 |
| P1 | **REPL UI** | 基本的终端交互界面 | 日常使用必需 |
| P1 | **认证** | API Key 认证 | 用户接入必需 |
| P1 | **Token 估算** | 基本的 token 计数 | 成本控制 |
| P1 | **AskUserQuestion** | 用户交互工具 | 提升体验 |

| 优先级 | 模块 | 功能 |
|--------|------|------|
| P2 | **Slash 命令** | /commit, /review, /compact 等 |

### 投资回报率最高的 20%

如果只实现一个最小可用版本，以下是最关键的模块:

```
1. API 流式调用 + Tool-Use Loop          (~15% 工作量, 核心价值)
2. 5 个核心工具 (Bash/Read/Write/Edit/Grep) (~10% 工作量, 基础能力)
3. 基础权限系统 (用户确认)                 (~5% 工作量, 安全底线)
4. 简单 CLI 入口 + 基础 REPL              (~10% 工作量, 用户入口)
5. 消息管理 + 系统提示词                   (~5% 工作量, 对话基础)

总计: ~45% 工作量覆盖 80% 核心价值
```

### 关键架构决策参考

1. **Tool 是一等公民**: 每个工具自包含（Schema + 权限 + 执行），通过注册表管理。新工具只需实现 `Tool` 接口
2. **Feature Flag 驱动**: 使用 `bun:bundle` 的 `feature()` 做编译时死代码消除，实现功能渐进式发布
3. **React/Ink 架构**: 终端 UI 使用 React 组件模型，所有状态通过 Hook 管理，极大地复用了 React 生态
4. **子 Agent 通过工具实现**: `AgentTool` 是一个普通工具，启动子进程执行独立对话循环，天然支持嵌套
5. **流式优先**: 从 API 调用到 UI 渲染全部流式，用户体验流畅
